- Exclude `casual`, `registered`: they sum to `cnt` exactly. Leaky model R^2 1.000 -> honest ridge 0.583.
- Exclude `cnt_2d_bfr`: a shipped 2-day lag we cannot test the alignment of. Build our own lags instead.
- Exclude `instant`, `yr`, `days_since_2011`: time indexes let a tree predict a flat constant past 2011 and a linear model extrapolate a trend we have no grounds for.
- Split 2011 / H1 2012 / H2 2012 by date. Test set touched once, after all feature work.
- Report mean and persistence baselines with every score. Persistence (test R^2 0.510, MAE 840) is within 0.07 R^2 of ridge and beats it on MAE; that caveat goes in the report.
- 2026-11-25 — Added `cnt_lag_3` (`cnt.shift(3)`, inside the existing `LAG_WARMUP = 7`, no warmup change): available at prediction time because the day d-3 count is recorded 3 days before the forecast. **RECOMMEND DROP** -- validation R^2 went *down* for both models (ridge 0.6475 -> 0.6462, -0.0013; hgb 0.2185 -> 0.1891, -0.0294), MAE up for both (ridge 832.9 -> 835.2; hgb 1296.6 -> 1318.2), and rows unchanged at 714. `cnt_lag_1` already carries the short-horizon signal, so lag 3 is redundant columns plus noise for the booster.
- 2026-11-25 — Target-transform experiment (`log1p` vs `sqrt` vs identity, via `TransformedTargetRegressor` with every metric scored on original `cnt` units after inverse transform; `experiments/transform_targets.py`, non-destructive, leakage-auditor run and clean on split integrity). **KEEP sqrt for ridge; DROP log1p; no transform for hgb.** ridge sqrt: valid R^2 0.6462 -> 0.6897 (+0.0435), MAE 835.2 -> 716.7 (-118.5); test R^2 0.5813 -> 0.6486 (+0.0673), MAE 947.4 -> 804.6 (-142.8). Chosen on validation alone and it holds on test, so it improves generalization on original `cnt` units -- and it closes the persistence gap in DECISIONS.md line 10: sqrt-ridge now beats persistence on test MAE (804.6 vs 840.1) as well as R^2. Mechanism is steady-day level tracking, not outlier handling: 167 quiet days MAE 870.1 -> 716.4 while 17 jump days are unchanged (1706.3 -> 1671.1), and test-set level bias shrinks from -553 to +28 rides/day. sqrt compresses the 2011->2012 growth so linear extrapolation lands nearer the 2012 level.
- 2026-11-25 — log1p's catastrophic test R^2 (-0.7177 vs identity +0.5813) is a **retransformation-level failure, not a fit failure, and must not be reported as "log1p fits worse."** It has the *lowest* log-space test RMSE of the three ridge variants (250 vs 283 identity, 279 sqrt); `expm1` then extrapolates the 2011 level to a mean prediction +1429 too HIGH (7472 vs actual 6043, max 13909 against a test maximum of 8714). Bias corrections fit on train residuals only do not rescue it (additive offset -> -0.7724; Duan smearing -> -0.9801). Caveat for the write-up: a concave transform with a naive inverse needs its mean-bias reported next to its R^2, or the comparison is unfair in whichever direction the bias runs.
- 2026-11-25 — hgb gets **no target transform**. It stays below the mean baseline on test under all three settings (identity -0.5653, log1p -0.6423, sqrt -0.5865) and its level bias remains ~-1900 rides/day; no monotone transform on the output fixes a tree plateauing at the 2011 range, which is the repo's headline result and should stay visible. Note the regime nuance the aggregate hides: hgb *beats* the mean baseline and ridge on the 17 jump days (MAE 1556.7 vs mean 2110.8, ridge 1706.3) and only loses badly on the 167 steady days (2073.2). "hgb is worse than a constant" is true in aggregate, not per regime.
- 2026-11-25 — sqrt adoption NOT yet wired into `src/train.py` `MODELS`: that would change the shipped `reports/metrics.json` for every model, so it needs an explicit go-ahead. Until then this is an experiment with a recommendation, not the pipeline.

Econometrically valid and leak-free, though it reduces the tree to predicting daily increments around persistence rather than learning level demand; committed `reports/metrics.json` remains on the untransformed baseline pipeline per assignment specification.
